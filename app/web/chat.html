Инварианты проекта

Инварианты — правила, которые агент не имеет права нарушить: выбранная архитектура, принятые технические решения, ограничения по стеку, бизнес-правила. Агент учитывает их в каждом ответе и не предлагает решения, которые их нарушают. Одно поле — один инвариант.

MCP-инструменты проекта

MCP (Model Context Protocol) — внешние источники данных для агента. Включённые серверы агент видит в каждом запросе: если для ответа не хватает фактов (погода, курс, цена), он сам вызывает нужный инструмент и отвечает по полученным данным, а не по догадке. Всё бесплатно и без ключей — интернет нужен только на время вызова.

Базы знаний проекта

RAG (Retrieval-Augmented Generation) — ответы по вашим документам. Файл разбирается на текст, режется на чанки, каждый чанк получает вектор (эмбеддинг) и метаданные: источник, заголовок, раздел и номер чанка. Индекс лежит ЛОКАЛЬНО, в проекте, и никуда не отправляется. Галочка включает базу у этого проекта: перед каждым запросом агент ищет в ней фрагменты по вопросу и отвечает по ним — под ответом видны источники. Документы не смешиваются с перепиской: они уходят в модель только на время запроса. Проверка: введите в чат команду /test_rag — прогон контрольных вопросов по включённым базам; ответы сверяются эталонами, выписанными из самой базы.

Поиск и ответы

Как документы попадают в ответ. Первый этап ищет кандидатов по смыслу и словам запроса, второй — реранкинг моделью-кросс-энкодером: она читает пару «вопрос + фрагмент» и решает, отвечает ли он (0…1). В ответ идут лучшие по этой оценке, а фрагменты, в которых модель уверена меньше порога, отбрасываются. Под ответом видно два числа: релевантность первичного поиска (косинус + слова, от 0 до 3) и оценка модели (0…1) — по ней и стоит настраивать строгость.

Периодическая задача

Задача повторяется сама: сервер заново выполняет её запрос через выбранный период и кладёт ответ в чат этой задачи — со свежими данными внешних инструментов проекта (если они включены у проекта: погода, курс, цена — набор инструментов меняется, повтор берёт то, что доступно). Период можно назвать и прямо в запросе: «Сводка погоды в Москве за последние сутки, раз в час». Задача не завершается и не проходит проверку результата — она повторяется, пока автозапуск включён; при отмене или удалении задачи (проекта) её сборы на серверах внешних инструментов останавливаются.

Учитываются токены запроса к модели: входящие (промпт с историей) и исходящие (ответ). Строка «Ответ шага» — только сам ответ модели по текущему шагу; «Весь диалог» — итог по всем замерам этого диалога, «из них служебные вызовы» — вклад вспомогательных вызовов, ниже он разложен по видам. Замеры накапливаются по ДИАЛОГУ: новый проект в том же диалоге продолжает тот же итог. Столбец «Лимит» показывает настройку «Длина» текущего запроса (красным — если входящие токены её превысили). Служебный здесь значит ВСПОМОГАТЕЛЬНЫЙ: результат вызова не является ответом пользователю (план задачи, проверка плана по правилам, разбор запроса по инвариантам, проверка результата, сжатие памяти, блок фактов, план ветвления). Строка «сбои» — обращения к модели, которые не удались: расхода по ним нет, но вызов был.
