# Локальные MCP-серверы проекта

Четыре сервера [MCP](https://modelcontextprotocol.io) (Model Context Protocol) на
официальном SDK `@modelcontextprotocol/sdk`. Три из них **бесплатные и без
ключей** (регистрация и API-токены не нужны, интернет требуется только в момент
вызова инструмента), а четвёртый — `git` — вообще не ходит в сеть: он читает
рабочую копию самого проекта.

| id | Название | Что даёт | Источник данных |
|---|---|---|---|
| `weather` | Погода | текущая погода и прогноз по дням для любого города | 7timer.info (NOAA GFS) + геокодер Open-Meteo |
| `currency` | Курсы валют | официальные курсы Банка России к рублю, перевод суммы, список курсов | cbr.ru |
| `crypto` | Криптовалюты | цены монет в обычных валютах, обзор рынка (капитализация, изменение за сутки и неделю) | CoinGecko |
| `git` | Git-репозиторий проекта | текущая ветка, последний коммит, список файлов, изменения (diff), история коммитов и содержимое файла | рабочая копия этого проекта (`git`) |

> Свои серверы проекта — `open_meteo` (погода, прогноз, качество воздуха,
> координаты) и `city_registry` (реестр городов и жителей) — здесь **не лежат**:
> это серверы `open-meteo-mcp` и `city-registry-mcp`, развёрнутые на VPS. В
> каталоге `mcp_servers/` только локальные процессы; удалённые серверы
> подключаются по Streamable HTTP через SSH-туннель, а их адреса и токены задают
> переменные `OPEN_METEO_MCP_URL` / `OPEN_METEO_MCP_TOKEN` и
> `CITY_REGISTRY_MCP_URL` / `CITY_REGISTRY_MCP_TOKEN` в `.env`.

## Как это работает

Приложение (`app/ai/mcp.py`) — клиент MCP с двумя транспортами: локальные
серверы оно запускает отдельным процессом и общается по **stdio** на языке
JSON-RPC 2.0 (`initialize` → `tools/list` → `tools/call`), а удалённые серверы
вызывает HTTP-запросом (Streamable HTTP). Сервер объявляет инструменты, а агент
вызывает их сам, когда для ответа не хватает фактов.

Включение — по кнопке **«MCP»** рядом с шестерёнкой проекта: галочки серверов и
«применить». Набор серверов — настройка ПРОЕКТА (`task["mcp"]`): включённые
серверы агент видит в каждом запросе, выключенные не запускаются вовсе.

## Сервер `git`: агент и ассистент разработчика

`git.mjs` даёт агенту то, чего у модели нет вовсе, — состояние рабочей копии
проекта. Пять инструментов, все **только на чтение**:

| инструмент | что отвечает |
|---|---|
| `git_status` | ветка, последний коммит, отслеживаемая ветка (впереди/отстала), изменённые файлы |
| `git_files` | файлы проекта (все или только изменённые), можно ограничить каталогом |
| `git_diff` | сами изменения: `working`, `staged`, `head` или `branch` (с базовой веткой), плюс `stat_only` |
| `git_log` | последние коммиты ветки (хеш, дата, автор, тема) |
| `git_show_file` | содержимое файла с номерами строк — рабочей копии или версии из ветки/коммита |

**Пустой `git_diff` — с разными причинами, и их называет сервер.** У НЕотслеживаемого файла (нового, `??`) diff пуст потому, что сравнивать не с чем — у него нет ни одной версии в истории; у игнорируемого — потому что git его не ведёт; у файла с правками только в индексе — с подсказкой «повтори со `scope=staged`»; у отслеживаемого и чистого — честное «изменений нет». Пустой diff без пути дополнительно называет новые файлы: их diff не показывается вовсе. Та же логика у `git_log`: «коммитов нет» у нового файла означает «истории не существует», а не «файл не менялся».

Запись в репозиторий через этот сервер **невозможна**: выполняются только
читающие команды, аргументы уходят в git списком (`execFile`, без оболочки),
`GIT_OPTIONAL_LOCKS=0` не даёт даже `status` обновлять индекс. Пути проверяются:
выход за корень репозитория, каталоги `.git/`, `data/`, `venv/`, `node_modules/` и
файлы с секретами (`.env`, ключи) закрыты. Ответы держатся в бюджете 3400
символов (клиент берёт не больше 4000) и честно говорят, что показано не всё.

Каталог репозитория — корень проекта; другой задаёт переменная `GIT_REPO_DIR`
(см. `.env.example`).

С этим сервером работает **команда `/help` в чате** — ассистент разработчика:
вопросы о самом проекте («как устроен поиск по базам знаний», «что делает
`app/ai/mcp.py`», «что изменилось в этой ветке»). Ответ строится по документации
проекта (базы знаний, кнопка «RAG») и по состоянию репозитория из этого сервера,
под ответом — источники с цитатами и переходом к чанку. Команда идёт мимо
пайплайна задачи: ни плана, ни шагов, ни автомата.

## Установка

Серверам нужен Node.js (18+) и один раз установленные зависимости:

```bash
cd mcp_servers
npm install
```

Каталог `node_modules/` в git не хранится (он большой). Если он отсутствует,
диалог «MCP» в приложении покажет у серверов причину «не установлен MCP SDK:
выполните npm install в каталоге mcp_servers» — инструменты при этом просто не
подключаются, остальное приложение работает как обычно.

Путь к Node.js можно задать переменной окружения `MCP_NODE_BIN`, каталог
серверов — `MCP_SERVERS_DIR` (см. `.env.example`).

## Проверка вручную

```bash
# список инструментов и вызов (сервер отвечает на stdin/stdout, лог — в stderr)
printf '%s\n' \
  '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"cli","version":"1"}}}' \
  '{"jsonrpc":"2.0","method":"notifications/initialized"}' \
  '{"jsonrpc":"2.0","id":2,"method":"tools/list"}' \
  '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"get_weather","arguments":{"city":"Москва"}}}' \
  | node weather.mjs

# сервер проекта: ветка и изменения
printf '%s\n' \
  '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"cli","version":"1"}}}' \
  '{"jsonrpc":"2.0","method":"notifications/initialized"}' \
  '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"git_status","arguments":{}}}' \
  | node git.mjs
```

Автоматические проверки: `./venv/bin/python tools/check_mcp.py` (клиент, маршруты
и работа MCP в диалоге агента — без сети и без Node) и
`./venv/bin/python tools/check_dev_help.py` (инструменты `git` на настоящем
временном репозитории, охрана путей, команда `/help` — тоже без сети).

## Свой сервер

Добавьте запись в `SERVERS` (`app/ai/mcp.py`): `id`, `name`, краткое
`description` для интерфейса, `source` и либо `script` (файл в этом каталоге,
запускается через `node`), либо готовую `command` — тогда подойдёт ЛЮБОЙ
MCP-сервер, включая сторонний на Python или npx. Протокол клиента от SDK не
зависит.
